## 2. 运行自动测试

在项目根目录使用 JDK 17，安装 Android SDK Platform 36 和 Build Tools 36.0.0，配置 `ANDROID_HOME`，或在未提交的 `local.properties` 中写入 `sdk.dir`。

```bash
chmod +x gradlew
./gradlew --no-daemon testDebugUnitTest assembleDebug lintDebug
```

首次运行需要联网下载 Gradle、Android 构建插件和测试依赖；应用本身运行不需要联网。常用结果路径：

- 单元测试报告：`app/build/reports/tests/testDebugUnitTest/index.html`。
- 单元测试 XML：`app/build/test-results/testDebugUnitTest/`。
- Lint 报告：`app/build/reports/lint-results-debug.html`。
- Debug APK：`app/build/outputs/apk/debug/app-debug.apk`。

如需仅运行某一测试类，使用 `./gradlew testDebugUnitTest --tests '完整包名.测试类名'`。不能以单元测试通过替代真实设备上的系统通知、绘制性能和触摸体验验收。

## 3. 核心测试设计

1.0.2 重点验证：档案/计划草稿三选一与旋转，导航/历史滚动及筛选恢复，无障碍前后项，未开始浏览不计记录，重复/陈旧回调，已完成待保存恢复，统一有效谓词与旧坏分保留，64Ki 字符分块和 4Mi 字符限制，坏轨迹断笔、事件 30 条分页与坏事件隔离。实际通过情况以本轮最终报告为准。

1.0.1 新增验证重点为同任务/难度筛选、跨档案及非法指标拒绝、会话总时限、旧触摸丢弃、保存失败后原状态/动作恢复、冷启动快照三选一、待投递提醒保留及 Android 13 权限路径。新增 `VisualRenderingTest` 使用原生 Skia 离屏绘制实际 Android View，输出 `app/build/outputs/previews/`，含空首页/训练选择/空统计/螺旋训练，以及以自动构造 MotionEvent 完成训练后由 SQLite 记录生成的成绩页，另验证窄屏长指标；这不是设备截图或真机验收。

| 范围 | 输入或操作 | 预期判定 |
| --- | --- | --- |
| 轨迹偏差 | 使用目标采样点本身作为实际路径，再使用明显偏离路径 | 贴合路径的偏差更低；偏离路径不能取得更高的准确度 |
| 轨迹完整性 | 空路径、单点、短线、只描绘目标局部、正确完整路径 | 空/短/低覆盖/起终点无效路径不成为有效完成；完整路径可通过有效性检查 |
| 坐标归一化 | 按比例缩放同一输入和绘图区 | 归一化偏差与评分基本一致，不随像素密度任意变化 |
| 轨迹稳定性 | 平滑等速路径与抖动路径 | 稳定性有限且在 0～1 范围；抖动不提高稳定性 |
| 评分边界 | 0 时长、空输入、极端数值、无成功操作 | 无崩溃、无 NaN/无穷大；输出在 0～100 范围；缺失测量保留为空 |
| 反应时间 | 目标出现后以单调时间点击 | 每轮时长非负；统计只使用成功轮的反应时间；系统日期变化不影响测量 |
| 点击口径 | 成功、错误、超时分别发生 | 准确率为成功/(成功+错误)，超时独立保存；分母为 0 时不伪造准确率 |
| 协调顺序 | 正确顺序、错序、区域外点击 | 错误使计数增加但不推进正确目标；正确点击才推进 |
| 连续点击 | 单次按下、移动、抬起；多指；过短间隔；超过事件上限 | 一次有效单指触摸最多记一次；防重复规则生效；无效事件不推进；达到 4,096 条保护上限时结束为未完成并保存实际事件 |
| 推荐规则 | 同任务、同难度有效记录不足 5 条；均分 85、60、低于 60 | 不足 5 条说明依据不足；达到 85 提升建议；低于 60 降低建议；边界与难度上下限正确 |
| SQLite 持久化 | 创建/更新档案、保存/查询/删除记录与计划、重新打开数据库 | 字段一致、外键归属正确；可选指标保留 NULL；删除不影响其他记录 |
| 防止重复保存 | 对同一 `sessionId` 重复保存 | 同一会话只有一条数据库记录 |
| 用户范围 | 使用不同用户或不属于当前用户的记录 ID 查询 | 查询、删除与统计遵守当前档案归属 |
| 空数据统计 | 无记录时读取首页、历史、统计、推荐 | 计数为 0，均分/最佳分为空，图表显示空状态，不生成示例成绩 |
| 计划完成率 | 今天已完成有效任务、未完成任务、前一天任务、其他类型任务 | 仅统计今天匹配模式的有效已完成记录；计划修改后及时重算 |
| 数据库升级 | 保留已有记录后执行受支持的版本升级 | 保留数据，不使用静默删表重建冒充升级 |

## 4. 真机完整验收流程

建议至少使用 Android 8.0（API 26）与 Android 13 或以上的手机各一台；包含较小屏幕与不同分辨率。准备一台 Android Studio/ADB 主机，并记录手机型号、Android 版本、APK 版本、测试日期和实际结果。首次测试使用干净安装；持久化测试不可清除应用数据。

### 4.1 安装、首次引导与档案

1. 执行 `adb install -r app/build/outputs/apk/debug/app-debug.apk`，从桌面打开“指尖康复”。
2. 首次进入应展示引导与档案入口。检查空昵称、非法年龄/每日次数是否阻止保存并给出可理解提示。
3. 保存昵称、可选年龄、惯用手、训练目标和每日次数；退出应用再打开，信息应保留。
4. 编辑档案后分别选择继续编辑、放弃、保存退出，并旋转后核对草稿；只有保存成功才更新首页信息。
5. 在没有训练记录时，首页、历史、统计与推荐应显示空状态，不能出现假成绩。

### 4.2 轨迹训练

1. 从“训练”选择直线、简单，先不点开始并返回，核对没有新增记录；再开始并按提示从起点沿蓝色目标线描绘至终点。
2. 观察青绿色实际路径、进度和计时变化；结束后检查得分、完成时间、偏差、覆盖率、稳定性及完成状态。
3. 分别完成圆形和螺旋线，再切换普通、困难，检查目标形状/容差/时间参数差异。
4. 分别尝试单点、只描一小段、横穿画布的短线、明显偏离目标、从错误起点开始。应被标为未完成或得分受到有效性限制，不能获得有效高分。
5. 点击重新开始，确认后应清空本次采样和计时；前次尝试不得计成已完成训练。
6. 在绘制中按返回键，应出现退出确认。取消后可继续；确认后应按中断流程结束，不计入计划完成次数。
7. 在训练中旋转手机、按 Home、切回应用；检查界面反馈与中断处理，不得静默丢失或重复保存。冷启动后再次进入训练页，分别检查恢复上次、保存中断并开始本次、保留数据返回三条路径；保存失败后重试应保留原状态与动作；已完成待保存的恢复不得改为中断或清零成绩。

### 4.3 反应速度训练

1. 选择简单，连续点击圆形目标直至规定轮数结束，观察轮次、剩余时间与命中反馈。
2. 在目标外点击 2 次，再命中；检查错误增加、当前目标仍存在，准确率口径正确。
3. 放置手机使一个目标超时；检查超时与错误分别统计、下一轮正常开始。
4. 完成简单、普通、困难，确认目标大小和时限有区别且圆形不超出有效区域。
5. 结果中核对成功、错误、超时、平均/最快反应时间与成绩；无成功轮时反应时间应显示“—”或说明，不能伪造 0 ms。
6. 训练中调整系统日期，再继续训练；反应测量不应出现负数或异常超长值。

### 4.4 协调性训练

1. 按顺序点击全部数字，确认只有当前数字可推进，结果保存正确次数、错误次数、时间与成绩。
2. 故意点击错误数字和空白区域；应有错误反馈且当前正确目标不变。
3. 完成连续点击任务：有效区域内每次单指点击推进一次；区域外点击只记错误或无效。
4. 按住、拖动、多指按下和极快点击，检查不能将一次触摸重复算作多次有效点击。
5. 检查平均点击间隔、节奏稳定性和未完成结果，不适用的指标应留空。

### 4.5 历史、结果和统计

1. 从结果页返回首页，今日次数、最近记录与最近成绩应来自刚才保存的数据。
2. 打开历史，检查按时间倒序、训练名称/难度/得分/时长、分批加载与筛选。
3. 点击历史记录查看报告；多于 30 条事件可逐组翻至最后，单个坏事件不影响其余项；返回与旋转应保留历史/事件页码和滚动，关闭重开应用记录仍在。
4. 删除一条记录时先取消，记录应保留；再次确认删除，列表与统计应更新。
5. 选择具体任务和难度，检查成绩折线、近 30 天趋势及近 7 天次数；切回混合任务/难度时不应连接成绩趋势。核对类型对比图说明的汇总范围、坐标和记录。
6. 为同一具体任务收集至少 5 次同难度有效结果，核对难度推荐依据；未完成、中断和不同难度记录不混入同一推荐样本。
7. 删除全部记录后，图表和平均分应回到空状态，不残留旧图形。

### 4.6 页面和布局

1. 依次切换“首页、训练、数据、计划、我的”，再进入档案、各训练、结果、历史、计划编辑和设置。
2. 使用系统返回键与应用返回入口，确认路由正常且不会反复堆叠同一页面。
3. 切换导航检查各页滚动保留，重开后难度/统计筛选保留；使用无障碍读值与前后项动作。在小屏、大字体、横屏/竖屏下检查标题、卡片、图表和按钮；内容应可滚动，训练画布应可用。
4. 连续完成多次训练，退出页面后观察计时器和动画不再错误运行，界面无明显卡顿或崩溃。

## 5. 计划与系统提醒验收

提醒使用系统非精确调度，不保证在设定分钟立即通知。系统待机、电池优化和厂商策略可能延迟投递；应用未申请精确闹钟特殊权限。

1. 创建今天的计划，设置模式、每日次数和未来时间，分别验证未保存返回的保存/放弃/继续编辑及旋转草稿；保存后重新进入页面确认持久化。
2. 完成一次匹配模式的有效任务；今日完成数和百分比应更新。未完成、中断及不匹配模式不增加完成数。
3. Android 13 及以上：首次启用提醒后允许通知权限，等待系统投递，点击通知应进入应用。
4. 再次干净安装并拒绝权限：保存计划不崩溃，显示权限状态与处理方式；之后从系统设置允许通知并重新保存/启用。
5. 把提醒时间改到稍后，旧时间不得再触发；关闭提醒或删除计划后不应收到旧任务通知。
6. 相同计划反复保存，核对只保留一个有效调度，不出现重复通知。
7. 开启提醒后重启设备，解锁并等待系统广播与计划时间，检查恢复调度。
8. 修改系统时区或日期/时间，检查下次提醒按本地时间重新安排。
9. 在勿扰模式、通知渠道关闭、电池省电、Doze/厂商后台限制下记录实际表现。系统限制导致延迟应写入实测记录，不能当作精确提醒已保证。
10. 强行停止应用后，Android 可能停止广播和闹钟投递；重新打开应用检查调度恢复。不要将“强行停止后仍会提醒”写成产品保证。
